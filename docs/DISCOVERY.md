## What the repo does, in one sentence

A Windows app (Rust backend + Tauri v2 shell + SvelteKit/Svelte 5 UI) that bypasses DPI-based
blocking of Discord/Roblox/YouTube via selectable packet-desync engines (bundled `winws`
sidecar, ByeDPI, GoodbyeDPI), a WARP VPN split-tunnel, and per-app throttling — with a
rollback journal, preflight checks, and DNS hardening.

## Entry points

- `src-tauri/Cargo.toml` — two binaries: `evorift` (UI app) and `evorift-svc` (privileged
  Windows LocalSystem service, spawned by the UI's `install_service` command).
- `src-tauri/src/main.rs` — Tauri v2 app + tray icon + GitHub-Releases auto-updater.
- `src/routes/+page.svelte` — main UI, 8 section tabs.
- Runtime modes (`src-tauri/src/lib.rs`, `runtime_mode` function): `service` (LocalSystem,
  persists without UI) / `serviceless` (elevated UI only, protection while UI is open) /
  `limited` (unelevated, no protection — banner tells the user to elevate). This 3-tier
  fallback is mature, not a half-migration; **v2 should preserve it.**

## Data flow (step by step)

```
UI action → Tauri command (lib.rs) → client.rs (IPC client) →
named pipe \\.\pipe\evorift-ipc.sock (line-delimited JSON) →
service.rs / engine.rs processes the Command →
mutates the system: spawn/kill winws sidecar (engine/winws.rs), configure
WinDivert filter, DNS changes (dns.rs via PowerShell/netsh/DoH), firewall
rules (firewall.rs, netsh advfirewall), service creation (svcctl.rs),
registry writes, bandwidth limiting (limit.rs, QoS/netsh), WARP tunnel
(warp.rs, WireGuard config) →
rollback.rs records the Change AFTER each mutation →
metrics stream back via Tauri event "telemetry" (~1 Hz) →
state.svelte.ts consumes it, UI re-renders.
```

## Half-done / stub / risky areas

1. **Bandwidth limiting (`set_limit`)** — code-complete (`state.svelte.ts`, IPC command wired)
   but the `<Limits />` UI section is hidden per an in-code comment ("rate-limiting REMOVED — …").
   Inbound WinDivert throttle not yet live-tested. Feeds directly into **V7.3** of the plan.
2. **Per-app domain auto-detection** (`state.svelte.ts:436-467`, `detect_app_domains` command) —
   adaptive backoff, CPU-aware, window-visibility-dependent. Documented but not stress-tested;
   flagged as a risk since CPU-spike bugs here map to the CHANGELOG's own note about the
   0.1.0–0.1.2 CPU issue (see V10.5 of the plan).
3. **WARP integration** (`src-tauri/src/warp.rs`, ~600 lines) — references a net3 solution doc,
   live-verified 2026-06-10 on Türkcell; carries hardcoded Discord IP ranges and WireGuard peer
   config with no fallback if Cloudflare's WARP API or endpoint IPs change.
4. **ByeDPI / GoodbyeDPI engines** — referenced by `preflight.rs` and `ipc::validate`, but
   `src-tauri/src/byedpi.rs` / `goodbyedpi.rs` were not reviewed in depth by the scout; flagged
   as unverified, not as broken.
5. **Community profile fetch** (`profile.rs:216-231`) — downloads a JSON preset bundle from a
   user-supplied HTTPS URL with strict URL validation, but **no hash pinning on the fetched
   bundle** — a compromised upstream could serve a bad profile. Relevant to `evorift-security-hygiene`.
6. **Game Mode snapshot** (`state.svelte.ts:250-260,735`) — persisted to localStorage so it
   survives a UI crash/restart, but if the *service* applies tweaks and then crashes, only
   `rollback.json` protects system state — the UI's snapshot and the service's rollback journal
   are two separate recovery paths that aren't unified.

## Out-of-plan observations (flagged, not investigated further — candidates for BACKLOG P3)

1. **The "no in-process engine" premise in the current CLAUDE.md is confirmed by code**:
   `engine.rs:5-15` states the old in-process WinDivert engine (`engine/real.rs`) was removed
   during the net3 migration; no such file exists in the repo today. No discrepancy found.
2. **`FRONTEND-CONTRACT.md` is enforced by a test** (`ipc.rs`, `contract_doc_covers_all_commands`)
   — v2 should keep publishing an equivalent contract doc, or the same test loses its anchor.
3. **ISP preset detection** (`autopilot.rs:89-100`) matches ISP names via hardcoded lowercase
   string comparison (Turkcell, SuperOnline, Vodafone, Kablonet) — brittle to ISP name variants;
   the community-preset download is the existing escape hatch.
4. **Test coverage is real and non-trivial** across all 5 core-migration modules (rollback,
   preflight, manifest, ipc, profile) — no TODO/FIXME found in them. These tests are good
   migration scaffolding: port them alongside their modules, only module paths change.
5. **`BlackHole.svelte`** exists as the dashboard's main protection-toggle hero button, gated by
   the health signal in `ipc.rs:356`. Per the hard rule, its internals were not reviewed — only
   its interface contract (health-signal gating) needs preserving in v2.
